# 多 agent 协作流程合约

## 角色（本环境只能星形：所有跨 agent 消息经 main 中转）

| 角色 | 产物 | 出口条件（机器可判定） |
| :-- | :-- | :-- |
| planner | 01_brief.md + 02_spec.md | spec 里每条需求都能写成一条测试 |
| builder | 代码 + 03_impl.md | pytest 全绿 + 黄金值一字不变 |
| reviewer | 04_review.md | 每条隐患带触发条件 + 复现命令 |
| tester | tests/test_x.py | 新测试在旧代码上会红，在新代码上会绿 |

## 交接只给三样

1. 产物路径
2. 只允许读哪几份文件
3. 出口条件（一条能跑的命令）

**禁止**把聊天记录粘给下一个 agent。他要的东西在文件里。

## 回流规则

- 测试红了 → 回 builder
- review 发现隐患 → 回 builder；若是"需求没定义" → 回 planner
- 同一个 bug 回流最多 2 次；第 3 次判定为规格错误，强制回 planner
- 每次回流必须新增一条会在旧代码上红的测试

## 三种失败模式（必须自查）

1. **共识漂移**：下一段必须自己读代码复核**关键事实**，不只复核结论。
2. **假完成**：不接受"已完成"，只接受"命令 + 输出"。
3. **回流震荡**：靠上面的 2 次上限止血。

## 人不可外包的四个签字点

1. ticket（为什么做）
2. spec（怎么算做完了）
3. 编码审查（口径 / 断言 / 边界 / 错误路径 / 可观测）
4. commit
