         视为未完成。
[就绪]   回复确认，陈述已加载的文档和当前配置状态，等待用户指令

# 阶段二：编码

5. 【模板锁定】AI 生成的代码必须严格遵循阶段零加载的模板文件：
   - 类名、方法名、继承关系与模板完全一致，不得自行增减公开方法
   - 只在模板标注"AI在此写入"的区域填入业务逻辑，禁止突破模板框架
   - 违规判定：未继承指定基类 / 缺少必需方法 / 使用模板之外的下单方式
6. 【变量来源】所有参数通过 config.get('模块.参数') 读取，禁止在代码中写死数字字面量
7. 【配置分流】
   - 研究员可调的业务参数           → config/application.yml（默认值写在类属性 DEFAULT_PARAMS 中）
   - 系统常量（路径/超时/种子等）   → config/constants.py
   - 不确定默认值的参数             → 填 null，标注 # TODO: 需要回测确定
8. 【禁止清单】
   - 禁止在 config/ 中创建不存在的变量后代码直接用（必须先定义再引用）
   - 禁止修改 config/ 中已有的常量，如需修改必须向用户确认
   - 禁止删除任何文件
   - 禁止 except Exception: pass
   - 禁止 fillna(0) 处理价格/收益率数据
   - 禁止使用绝对路径，一律 pathlib
   - 禁止 iterrows()，一律向量化
   - 禁止新增依赖而不更新 requirements.txt
# >>> 新增 8.1【TDD 先行】（所有档位都建议做）
#     在新会话里说：「先用 skill tdd，按 02_spec.md 实现：
#       先写一条在现有代码上会红的测试，再写让它变绿的最小实现。」
#     三条硬要求：
#       ① 亲眼看到 RED（真实断言失败，不是 assert False）

#          —— 绝不能用被测函数自己算期望值（tautological，永远不会红）
#       ③ 一次只推进一个测试
# >>> 新增 8.2【大数组纪律】（本项目血的教训，见 PITFALLS #24）
#     - > 1000 万格的数组：先 np.full 铺满，再逐格写；禁止 np.empty
#     - 不把"写满数组"的责任交给库（rolling / where / ffill / reindex / loc / [cols] / corr / rank / copy）
#     - 大数组交接：零拷贝；必须拷则拷贝后校验 + 重试
#     - 日志里禁止 .get(key, 默认值) —— 取不到就报错，别伪装成正常
# >>> 新增 8.3【结果要能被机器判定】
#     每张卡/每个改动都要有 acceptance：一条能跑的命令
#       python -m pytest                  （当前基线 38 条）

# ============================================================
# 阶段三：审查（循环入口）
#   ★ skill: code-review（9.2 两轴评审）· 9.1 人审五条由【人】做
# ============================================================
9. 【AI 自审】代码生成完毕后，AI 对照 金融逻辑审查.md 的 14 条陷阱逐项检查：
   - 未来函数？→ 搜索 shift(-1)、iloc[-1]
   - 幸存者偏差？→ 确认是否标注
   - 复权问题？→ 确认使用的价格字段
   - 涨跌停？→ 确认价格校验逻辑
   - 时间戳？→ 确认时区强制
   - 财报日期？→ 如涉及财务数据，确认发布日期 vs 报告期
   - NaN 处理？→ 确认无 fillna(0)，ffill 有限制
   - 停牌陷阱？→ 确认连续 NaN 检测
   - 除权除息？→ 确认 adj_close 标注
   - 节假日空数据？→ 确认 empty 时 raise
   - 类型转换？→ 确认 config.get() 返回值被显式 cast
   - 引用传递？→ 确认 DataFrame 切片有 .copy()
   - 日志可审计？→ 确认 except 含 traceback
   - 除权日与涨跌幅冲突？→ 确认协调机制
   每一项标记 ✅ 或 ⚠️，⚠️ 项必须附带修复建议
10.【人工 Review】用户审查代码并添加业务注释
11.【修复循环】
   - 审查发现逻辑漏洞 → 回到阶段二修改代码 → 再次审查
   - 审查发现参数不合理 → 修改 application.yml → 重新跑验证
   - 审查通过 → 进入阶段四

# ============================================================
# AI 红线（QD_GUIDE.md 第 8 节 — 触犯即拒）
# ============================================================
1.  不生成前端代码
2.  不修改风控参数（只能从 YAML 读取）
3.  不自动执行 pip install / rm -rf / git push
4.  不替用户做工程决策（只给方案对比，让用户选）
5.  不删除任何文件
6.  不覆盖 settings.py / constants.py
7.  修改已有配置前必须询问确认
# >>> 新增 8.  不写"看起来通过"的测试：期望值不许用被测实现重算（tautological）
# >>> 新增 9.  不放宽断言来让测试变绿
# >>> 新增 10. 不把"已完成"当成证据 —— 只认命令和输出
